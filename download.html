Get Kite Helper

You only need this if you want to run an agent. Talking to a model — a hosted provider, or one on your own machine — needs nothing installed on any computer: set the endpoint in Kite and you are done.

For an agent, the Kite app talks to Kite Helper, which runs beside it and holds its credentials. You need it once, on whichever machine the agent lives on.

Why it exists

Your agent's API key grants full access to the machine it runs on — it can run commands there. Kite Helper means that key stays on that machine: your phone gets a pairing token instead, which can be revoked without touching your agent's configuration.

Without it your phone would have to hold the key itself, and a lost phone would be a shell on your computer.

On a Linux server

One file, Python 3.11 or newer, nothing to install. Run it beside your agent:

curl -O https://kiteagent.app/downloads/kite-helper.py
python3 kite-helper.py --gateway 127.0.0.1:8642

It prints a pairing link — scan it with Kite, or paste it in.

To keep it running:

curl -O https://kiteagent.app/downloads/kite-helper.service
sudo cp kite-helper.service /etc/systemd/system/kite-helper@.service
sudo systemctl enable --now kite-helper@$USER

You will also need a private path from your phone to the server — Tailscale is the simplest. Do not open the helper's port to the internet: a pairing token is all that stands between a caller and an agent that can run commands.

No agent on the server yet?

Kite Helper connects your phone to an agent — it does not provide one. If the server has no Hermes on it, this installs it headless and writes a start script:

curl -O https://kiteagent.app/downloads/install-hermes-server.sh
bash install-hermes-server.sh

Then put your OpenRouter key in ~/.hermes/.env and start it with ~/kite-hermes/run-agent.sh.

About free models. The installer picks a free model so it works the moment you have a key. Be aware what that buys: an OpenRouter key with no credits has a small daily allowance, and every step your agent takes is a request — one question that reads a few files can be twenty. A day of ordinary use will exhaust it.

When it runs out you get 429 Rate limit exceeded: free-models-per-day. OpenRouter's own remedy is to add 10 credits, which raises the free-model allowance to 1,000 requests a day — you keep using free models, the credits just unlock the higher tier. The counter resets daily at 00:00 UTC.

Two things that will waste your afternoon otherwise. The agent must be started with hermes gateway — not hermes serve, which is the desktop dashboard's backend. Both answer on /api/sessions, so picking the wrong one gives you a server that looks right and returns 405 to every message.

And aiohttp is not installed by default. Without it the agent starts, logs “API Server: aiohttp not installed”, binds no port, and does not exit — so it appears healthy while nothing can connect. The script above installs it.

Roughly 370 MB on disk and about 190 MB of memory while answering. It runs on a 1 GB server, though not with much to spare.

On a Mac

A small menu-bar app. It finds your agent, shows a pairing code, and otherwise stays out of the way.

Download Kite Helper 582 KB · macOS 14 or later · signed and notarised by Apple

SHA-256 0694652bb178e2b10cb4be9cdd2145a8f2ff20e2d8521cbbb4b97fe9f855867f

Why it is not on the Mac App Store. Kite Helper reads your agent's own configuration and connects to a service it did not start. Sandboxed apps may do neither, and both are exactly what it is for — so it ships signed and notarised from here instead. macOS will verify it with Apple on first launch and open it without a warning.

Which machine should run my agent?

  • Your Mac — simplest, and your files and tools are already there. It has to be awake for your phone to reach it.
  • A server — always on, reachable from anywhere on your private network, and nothing on your desk needs to stay running. Your agent's tools then act on the server, not your Mac.

Kite works the same either way. The helper is what makes them interchangeable.
